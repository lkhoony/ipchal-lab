# ipchal-lab 사용자 매뉴얼

입찰 데이터를 보고, 모델이 참고할 값(**feature**)을 만들고, 모델을 비교해 운영에 올리는 일을 **Claude에게 말로 시켜서** 하는 도구입니다. 명령어를 외울 필요는 없습니다. 문장으로 말하면 Claude가 알맞은 명령을 대신 실행하고 결과를 쉬운 말로 풀어 줍니다.

| 할 수 있는 일 | 예시 질문 |
|---|---|
| 데이터 보기·통계 분석 | "2025년 낙찰하한율별 평균 예가율 보여 줘" |
| feature 보기·만들기·고치기 | "같은 공고기관의 최근 20건 평균 예가율을 feature로 만들어 줘" |
| 모델 실험 (feature 조합 비교) | "이 feature들로 모델 만들어서 운영 모델이랑 비교해 줘" |
| 운영 반영·되돌리기 | "이 실험 서빙해 줘", "v03으로 되돌려 줘" |
| 비용 확인 | "이번 달 GCP 얼마 썼어?" |

---

## 1. 준비물

| 준비물 | 어디서 |
|---|---|
| Claude 계정 (Pro·Max·Team·Enterprise 요금제. 무료 요금제에는 Claude Code가 없습니다) | https://claude.ai |
| Claude 데스크톱 앱 **또는** Claude Code(터미널) | https://claude.ai/download |
| 설정 파일 `ipchal-lab.env` | 담당자에게 받기 (비공개) |
| 데이터 안내서 `ipchal-data-guide.md` | 담당자에게 받기 (비공개) |
| 공유 Google 계정 로그인 방법 | 담당자에게 받기 |

Python, Homebrew, git 같은 개발 도구는 **미리 설치하지 않아도 됩니다.** 처음 시작할 때 Claude가 필요한 것을 플러그인 전용 폴더에 알아서 설치합니다.

> 설정 파일과 데이터 안내서에는 회사의 프로젝트 이름이 들어 있습니다. 메신저 단체방, 공개 저장소, 블로그 같은 곳에 올리지 마세요.

## 2. 설치 (처음 한 번)

둘 중 편한 쪽 하나만 하면 됩니다. 처음이라면 **A. 데스크톱 앱**을 권합니다. 같은 PC에서는 한쪽에 설치하면 다른 쪽에서도 보입니다.

### A. Claude 데스크톱 앱에서

1. Claude 데스크톱 앱을 열고 로그인한 뒤, 위쪽의 **Code** 탭으로 갑니다. (일반 대화(Chat) 탭이 아니라 **Code** 탭이어야 합니다.)
2. 작업 폴더를 하나 고릅니다. 예: 문서 폴더 안에 `ipchal` 폴더를 새로 만들어 선택. 앞으로 만드는 SQL 파일 같은 작업물이 여기에 저장됩니다.
3. 입력창에 아래 두 줄을 **한 줄씩** 입력하고 보냅니다.

```
/plugin marketplace add lkhoony/ipchal-lab
```

```
/plugin install ipchal-lab@ipchal-lab
```

   설치 범위를 물으면 **사용자(User)** 를 고릅니다. 어느 작업 폴더에서든 쓸 수 있습니다.

4. Claude 앱을 완전히 껐다가 다시 켜고, Code 탭에서 같은 작업 폴더를 엽니다.
5. 입력창 옆 **+** 버튼 → **플러그인(Plugins)** → **플러그인 관리(Manage plugins)** 에 `ipchal-lab` 이 켜져 있으면 성공입니다. [2.1 "시작할래"](#21-시작할래)로 넘어갑니다.

> 3번의 입력이 동작하지 않으면 **B. Claude Code(터미널)** 방법으로 한 번만 설치하세요. 같은 PC의 데스크톱 앱 Code 탭에서도 그대로 보입니다.

### B. Claude Code(터미널)에서

1. Claude Code를 설치합니다. 이미 있으면 건너뜁니다.
   - Mac: **터미널** 앱을 열고

     ```
     curl -fsSL https://claude.ai/install.sh | bash
     ```

   - Windows: **PowerShell** 을 열고

     ```
     irm https://claude.ai/install.ps1 | iex
     ```

   새 터미널 창을 열어 `claude --version` 이 나오면 설치된 것입니다. (Mac은 macOS 13 이상, Windows는 Windows 10 1809 이상이 필요합니다.)

2. 작업 폴더를 만들고 그 안에서 `claude` 를 실행합니다. 처음이면 안내에 따라 Claude 계정으로 로그인합니다.

   - Mac:

     ```
     mkdir -p ~/Documents/ipchal && cd ~/Documents/ipchal && claude
     ```

   - Windows (PowerShell):

     ```
     mkdir $HOME\Documents\ipchal -Force; cd $HOME\Documents\ipchal; claude
     ```

3. Claude Code 입력창에 아래 두 줄을 한 줄씩 입력합니다. 설치 범위를 물으면 **사용자(User)** 를 고릅니다.

```
/plugin marketplace add lkhoony/ipchal-lab
```

```
/plugin install ipchal-lab@ipchal-lab
```

4. "Run /reload-plugins to apply" 가 나오면 `/reload-plugins` 를 입력합니다. 그다음 [2.1 "시작할래"](#21-시작할래)로 넘어갑니다.

### 2.1 "시작할래"

입력창에 **시작할래** 라고 말합니다. Claude가 아래 순서로 진행하며, 중간중간 묻는 말에 답하면 됩니다.

1. **도구 설치:** `ipchal` 프로그램과 그 프로그램 전용 Python을 내려받습니다. 처음에는 몇 분 걸립니다. 모두 **이 플러그인 전용 폴더**(`~/.claude/plugins/data/ipchal-lab-ipchal-lab/`)에만 들어가고, PC의 다른 프로그램이나 작업 폴더는 건드리지 않습니다.
2. **설정 파일 위치:** 담당자에게 받은 두 파일이 어디 있는지 묻습니다. 보통 다운로드 폴더에 있습니다. 데스크톱 앱이라면 파일을 채팅창으로 끌어다 놓아도 됩니다.
3. **이름:** 내가 만든 feature와 실험에 "만든 사람"으로 남는 이름입니다.
4. **로그인:** 브라우저 창이 열립니다. 담당자가 알려 준 공유 Google 계정으로 로그인하고 **허용**을 누릅니다.
5. **점검:** 모든 항목에 ✓ 가 나오면 준비가 끝난 것입니다. 이번 달 GCP 사용액과 한도도 함께 나옵니다.

```
✓ 설정을 읽었습니다
✓ 로그인 정보가 있습니다
✓ BigQuery 조회가 됩니다
✓ 합계 약 0원 / 한도 100,000원 (남은 금액 약 100,000원)
✓ GCS 저장소에 접근할 수 있습니다
✓ 모델 라이브러리(lightgbm)를 불러올 수 있습니다
✓ 버전 0.4.0
```

> Claude가 명령을 실행해도 되는지 물으면 **허용**을 누르세요. 설치 스크립트와 `ipchal` 명령만 실행합니다.

✗ 표시가 나오면 그 줄을 그대로 Claude에게 물어보세요 ("이거 무슨 뜻이야?"). 그래도 안 되면 그 화면을 담당자에게 보내 주세요.

### 2.2 업데이트

담당자가 새 버전을 알리거나 점검에서 "버전이 다릅니다"가 나오면:

1. 입력창에 `/plugin marketplace update ipchal-lab` 을 입력합니다. (새 버전 목록을 받아 옵니다.)
2. `/plugin` 을 입력하고 **Installed(설치됨)** 탭 → `ipchal-lab` → **Update now** 를 고릅니다.
   - 터미널이라면 대신 Claude 밖에서 `claude plugin update ipchal-lab@ipchal-lab` 을 실행해도 됩니다.
   - 데스크톱 앱에서 2번이 안 되면 터미널에서 한 번 실행하세요. 같은 PC면 앱에도 반영됩니다.
3. `/reload-plugins` 를 입력하거나 Claude를 껐다 켭니다.
4. **업데이트해 줘** 라고 말합니다. Claude가 `ipchal` 프로그램을 새 버전으로 다시 설치하고 점검합니다.

> 매번 하기 번거로우면 `/plugin` → **Marketplaces** 탭 → `ipchal-lab` → **Enable auto-update** 로 자동 업데이트를 켤 수 있습니다. 그래도 4번("업데이트해 줘")은 직접 해야 합니다.

## 4. 데이터 보기

### 4.1 기본은 model_base

조회와 통계는 기본적으로 **model_base**(모델용 기준 데이터)에서 합니다. 공고 1건이 1행이고, 원본 표들을 정리해 합쳐 둔 것이라 바로 분석하기 좋습니다.

| 묶음 | 주요 컬럼 |
|---|---|
| 공고 | 공고번호, 차수, 용역명, 공고기관, 공고일시, 개찰일시 |
| 금액 | 기초금액, log_기초금액, 낙찰하한율, 예비가격범위, 예정가격, 최종낙찰금액 |
| 분류·지역 | 대분류·중분류·세부분류, 시도, 시군구있음, 지역수, 업종_정리, 업종수, 학습범위_업종 |
| 결과 | 참여업체수, **예가율** |

### 4.2 예가율

**예가율**은 모델이 맞히려는 값입니다. 최종낙찰금액이 낙찰하한가보다 몇 % 높은지입니다.

```
예가율 = (최종낙찰금액 ÷ (기초금액 × 낙찰하한율 ÷ 100) − 1) × 100
```

- 0이면 하한가에 딱 맞춰 낙찰, 0.5면 하한가보다 0.5% 높게 낙찰된 것입니다.
- 아직 개찰 전인 공고는 비어 있습니다.
- 데이터 안에서는 열 이름이 `y` 입니다. 결과 표에는 자동으로 "예가율"로 표시됩니다.

### 4.3 원본 데이터가 필요할 때

"원본으로 봐 줘", "개찰 결과 원본에서 업체별 투찰 내역 보여 줘"처럼 **원본**을 분명히 말하면, Claude가 먼저 되묻습니다.

> "model_base가 아니라 원본 테이블 ○○을 조회할까요? 원본은 조회량이 크고 같은 공고가 여러 번 들어 있을 수 있습니다."

"응"이라고 답해야 원본을 읽습니다. 원본에 있는 대표자명·연락처·주소 같은 개인정보는 결과에 보여 주지 않습니다.

### 4.4 데이터 기간

2016년부터 지금까지 빈 구간 없이 있고, 매일 아침 새 공고와 개찰 결과가 더해집니다. 가장 최근 공고는 아직 개찰 전이라 예가율이 비어 있습니다.

## 5. 비용 한도

BigQuery는 읽은 데이터 양만큼 비용이 듭니다. 그래서 데이터를 읽기 전에 항상 이번 달 사용액을 먼저 확인합니다.

```
이번 달 GCP 사용액 약 3,200원 / 한도 100,000원 (남은 금액 약 96,800원)
…(결과)…
이번 작업 조회 1.40 GB, 약 0원
```

- **이번 달 사용액 + 이번 조회 예상**이 월 한도(기본 10만 원)를 넘으면 **실행되지 않습니다.** 그때는 담당자에게 알려 주세요.
- 매달 처음 1 TiB(약 1,000 GB)까지는 무료라, 평소 사용에서는 대부분 0원으로 나옵니다.
- 한 번에 아주 많이 읽는 조회는 예상 조회량(GB)을 먼저 보여 주고 진행할지 묻습니다. 이유를 모르겠는 큰 조회(수십 GB 이상)는 담당자에게 먼저 물어보세요.
- "이번 달 얼마 썼어?"라고 물으면 자세한 내역을 볼 수 있습니다.

## 6. feature

**feature**는 모델이 공고 하나를 보고 계산하는 "참고 값"입니다. 예를 들어 "같은 낙찰하한율 공고의 최근 20건 평균 예가율"이 하나의 feature입니다.

### 6.1 상태

| 상태 | 뜻 |
|---|---|
| 검사통과 | 실험에 쓸 수 있음 |
| 초안 | 검사에서 문제가 나와 고쳐야 함 (실험에 못 씀) |
| 폐기 | 더 이상 쓰지 않음 (기록은 남음) |

### 6.2 만들기

아이디어를 말하면 Claude가 SQL로 만들어 미리 보여 주고, 확인을 받은 뒤 검사를 거쳐 등록합니다.

> 나: 같은 공고기관의 최근 20건 평균 예가율을 feature로 추가해 줘
>
> Claude: (비슷한 feature가 있는지 확인 → SQL 작성 → 최근 한 달 공고로 미리보기)
> "최근 한 달 공고 1,234건 중 1,100건에 값이 나왔고, 나머지는 과거 기록이 없는 기관이라 비어 있습니다. 이름은 `기관_최근20_평균`, 설명은 '같은 공고기관의 직전 20건 평균 예가율'로 등록할까요?"
>
> 나: 응
>
> Claude: (검사 몇 분) "검사를 통과했습니다. 이제 실험에 쓸 수 있습니다."

등록할 때 자동으로 하는 검사:

- **형식:** 공고마다 값이 정확히 하나씩 나오는지
- **빈 값:** 값이 전부 비어 있지 않은지
- **미래 정보:** 공고 개찰일 기준 **7일 전보다 앞선 결과만** 썼는지. 개찰 직전 결과를 쓰면 실제 예측할 때는 알 수 없는 정보를 쓰는 셈이라 막습니다.
- **비용:** 계산할 때 너무 많이 조회하지 않는지

검사에 실패하면 **초안**으로 저장되고 Claude가 이유를 설명합니다. "고쳐 줘"라고 하면 고쳐서 다시 검사합니다.

> feature를 만들거나 고쳐도 **운영 중인 모델에는 아무 영향이 없습니다.** 실험하고, 승인해야 운영에 들어갑니다.

## 7. 모델 실험

- "기관_최근20_평균이랑 낙찰하한율로 모델 만들어 줘"
- "지금 운영 모델 feature에 기관_최근20_평균을 더하면 좋아져?"

모든 실험은 **같은 기준**으로 평가됩니다. 데이터의 마지막 12개월로 평가하고, 그 이전 데이터로 학습합니다. 몇 분에서 수십 분 걸리며, 끝나면 비교표가 나옵니다. 실험은 기록만 남기고 운영에는 영향이 없습니다.

| 비교 대상 | 뜻 |
|---|---|
| 실험 | 내가 고른 feature 조합 |
| 경험 분포 | feature 없이 과거에 자주 나온 예가율 구간만으로 찍었을 때 |
| 현재 서빙 | 지금 운영 모델의 feature로 같은 기간 학습·평가한 결과 |

보는 법:

- **0.01 적중률 (주 지표):** 예가율을 0.01%p 단위 칸으로 나눴을 때, 모델이 가장 가능성 높다고 고른 5칸 안에 실제 결과가 들어간 공고의 비율입니다. 높을수록 좋습니다.
- **0.1 적중률:** 같은 방식을 0.1%p 칸으로 잰 값입니다.
- **± (표준오차):** 평가 공고 수가 한정되어 생기는 흔들림입니다. **두 점수 차이가 이 값의 2배보다 작으면 "우연일 수 있다"**는 뜻입니다. Claude가 함께 판단해 줍니다.
- 같은 feature로 다시 학습해도 점수가 0.2%p 정도 흔들릴 수 있습니다. 작은 차이로 결론 내리지 마세요.

실험 기록은 자동으로 남습니다. "실험 목록 보여 줘", "실험 exp-… 다시 보여 줘"로 다시 볼 수 있습니다.

## 8. 운영 반영과 되돌리기

### 8.1 요청 → 승인

> 나: 이 실험 서빙해 줘
>
> Claude: (비교표를 다시 설명) "요청 이유를 한두 문장으로 알려 주세요."

요청은 "이 실험을 올리자"는 기록일 뿐이라 **운영은 아직 그대로**입니다. 요청과 승인은 누구나 할 수 있습니다.

> 나: 승인해 줘
>
> Claude: "승인하면 이 모델이 **운영 모델**이 됩니다. 지금 운영 모델보다 0.01 적중률이 0.2%p 높지만 우연 범위 안이라 좋아졌다고 말하기 어렵습니다. 되돌릴 수는 있지만 새 버전 파일은 영구히 남습니다. 확신이 없으면 팀과 먼저 이야기해 보세요. 운영에 반영할까요?"
>
> 나: 응, 반영해 줘

Claude는 승인 직전에 **항상** 무엇이 바뀌는지와 근거를 설명하고 다시 묻습니다. 분명히 "예"라고 답해야 진행됩니다.

승인하면 그 feature 조합으로 **전체 기간 데이터로 다시 학습**한 뒤 새 버전(v01, v02 …)으로 저장하고 운영을 전환합니다. 몇 분에서 수십 분 걸립니다.

> 서비스에서는 운영 모델에 들어 있는 feature 중 원하는 것만 골라(체크해) 예측할 수 있습니다. 그래서 운영 모델의 feature 목록이 곧 서비스에서 고를 수 있는 선택지입니다.

### 8.2 반려·되돌리기·상태 보기

- "반려해 줘, 이유는 …": 요청을 반려하고 이유를 남깁니다.
- "v03으로 되돌려 줘": 예전 버전으로 되돌립니다. 이때도 Claude가 먼저 확인합니다. 예전 파일은 지워지지 않아서 다시 돌아갈 수도 있습니다.
- "지금 운영 모델 뭐야?": 운영 버전, 점수, feature, 학습 기간을 봅니다.

승인 후 실제 서비스에서 무엇이 바뀌는지는 [운영 워크플로](operations-workflow.md)를 보세요.

## 9. 지켜 주세요

- 모든 작업은 Claude와 `ipchal` 명령으로만 합니다. Google Cloud 콘솔이나 다른 도구로 직접 테이블을 고치지 마세요. 공유 계정은 권한이 커서, 프로그램 밖에서 하면 실수를 막을 수 없습니다.
- 비용 한도에 막히면 우회하지 말고 담당자에게 알려 주세요.
- 운영 반영(승인·되돌리기)은 팀 전체에 영향을 줍니다. 확신이 없으면 팀과 먼저 이야기하세요.
- 원본 데이터의 개인정보(대표자명·연락처·주소)는 캡처하거나 공유하지 마세요.
- 설정 파일·데이터 안내서·로그인 정보는 공유하지 마세요.

## 10. 자주 묻는 질문

**Q. 일반 대화(Chat) 탭에서도 되나요?**
안 됩니다. 이 도구는 PC에서 `ipchal` 프로그램을 실행해야 해서 데스크톱 앱의 **Code** 탭이나 터미널의 Claude Code에서만 동작합니다.

**Q. "버전이 다릅니다"라고 나와요.**
[2.2 업데이트](#22-업데이트) 순서대로 하세요.

**Q. 플러그인 스킬이 안 보여요 / "시작할래"에 반응이 없어요.**
`/reload-plugins` 를 입력하거나 Claude를 껐다 켜세요. 그래도 안 되면 `/plugin` → **Installed** 탭에 `ipchal-lab` 이 켜져 있는지 확인하세요.

**Q. 로그인 창이 안 떠요 / 로그인이 풀렸어요.**
"로그인 다시 해 줘"라고 말하세요.

**Q. "월 한도를 넘어 실행하지 않았습니다"가 나와요.**
이번 달 GCP 사용액이 한도에 가까워졌다는 뜻입니다. 담당자에게 알려 주세요. "이번 달 얼마 썼어?"로 내역을 볼 수 있습니다.

**Q. "사용액을 확인할 수 없어 실행하지 않았습니다"가 나와요.**
로그인한 계정에 사용액을 볼 권한이 없다는 뜻입니다. 그 메시지를 담당자에게 보내 주세요.

**Q. 원본 테이블을 보고 싶어요.**
"원본으로 보여 줘"라고 분명히 말하면 Claude가 확인한 뒤 조회합니다. 대부분의 분석은 model_base로 충분합니다.

**Q. 실험이 너무 오래 걸려요.**
feature가 많을수록 오래 걸립니다. 처음에는 2~5개로 시작하세요.

**Q. 내가 만든 feature를 지우고 싶어요.**
"이 feature 폐기해 줘"라고 하면 폐기 상태가 됩니다. 기록은 남습니다.

**Q. 다 지우고 싶어요.**
`/plugin uninstall ipchal-lab@ipchal-lab` 으로 플러그인을 삭제하면 프로그램, Python, 설정 파일, 로그인 정보가 들어 있는 전용 폴더도 같이 지워집니다. 작업 폴더에 만든 SQL 파일은 직접 지우면 됩니다.

**Q. Windows에서도 되나요?**
됩니다. 설치 과정만 조금 다르고, Claude가 운영체제에 맞게 진행합니다. 모델 라이브러리를 불러올 수 없다는 메시지가 나오면, 점검 결과에 나온 Microsoft 링크로 구성 요소를 설치하세요.
