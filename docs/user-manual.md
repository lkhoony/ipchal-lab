# ipchal-lab 사용자 매뉴얼

이 매뉴얼은 개발을 몰라도 Claude에게 말로 시켜서 아래 일을 할 수 있게 안내합니다.

1. 입찰 데이터(BigQuery)를 둘러본다
2. 모델이 참고할 값(**feature**)을 새로 만들어 본다
3. feature 조합으로 모델을 만들어 지금 운영 중인 모델과 비교한다
4. 확실히 더 좋으면 운영에 반영한다 (요청 → 승인)

명령어를 외울 필요는 없습니다. 문장으로 말하면 Claude가 알맞은 명령을 대신 실행하고 결과를 쉬운 말로 풀어 줍니다.

---

## 1. 준비물

| 준비물 | 어디서 |
|---|---|
| Claude 데스크톱 앱과 로그인할 계정 | https://claude.ai/download |
| 설정 파일 `ipchal-lab.env` | 담당자에게 받기 (비공개, 다른 곳에 올리지 마세요) |
| 데이터 안내서 `ipchal-data-guide.md` | 담당자에게 받기 (비공개) |
| 공유 Google 계정 로그인 방법 | 담당자에게 받기 |

Python, Homebrew, git 같은 개발 도구는 **미리 설치하지 않아도 됩니다.** 처음 시작할 때 Claude가 필요한 것을 알아서 설치합니다.

> 설정 파일과 데이터 안내서에는 회사의 프로젝트 이름이 들어 있습니다. 메신저 단체방, 공개 저장소, 블로그 같은 곳에 올리지 마세요.

---

## 2. 설치 (처음 한 번)

### 2.1 플러그인 추가

1. Claude 데스크톱 앱을 열고 **Code** 탭으로 갑니다.
2. 작업 폴더를 하나 고릅니다 (예: 문서 폴더 안에 `ipchal` 폴더를 새로 만들어 선택). 앞으로 만드는 SQL 파일 같은 작업물이 여기에 저장됩니다.
3. 입력창에 아래 두 줄을 한 줄씩 입력합니다.

```
/plugin marketplace add https://raw.githubusercontent.com/lkhoony/ipchal-lab/main/.claude-plugin/marketplace.json
```

```
/plugin install ipchal-lab@ipchal-lab
```

4. 설치가 끝나면 Claude 앱을 한 번 껐다 켭니다.

### 2.2 "시작할래"

입력창에 **시작할래** 라고 말합니다. Claude가 아래 순서로 진행하며, 중간중간 묻는 말에 답하면 됩니다.

1. **도구 설치:** `ipchal` 프로그램과 그 프로그램 전용 Python을 내려받습니다. 처음에는 몇 분 걸립니다. 모두 **이 플러그인 전용 폴더**(`~/.claude/plugins/data/ipchal-lab-ipchal-lab/`)에만 들어가고, PC의 다른 프로그램이나 작업 폴더는 건드리지 않습니다.
2. **설정 파일 위치:** 담당자에게 받은 두 파일이 어디 있는지 묻습니다. 보통 다운로드 폴더에 있습니다. 파일을 채팅창으로 끌어다 놓아도 됩니다.
3. **이름:** 내가 만든 feature와 실험에 "만든 사람"으로 남는 이름입니다.
4. **로그인:** 브라우저 창이 열립니다. 담당자가 알려 준 공유 Google 계정으로 로그인하고 **허용**을 누릅니다.
5. **점검:** 모든 항목에 ✓ 가 나오면 준비가 끝난 것입니다.

> Claude가 명령을 실행해도 되는지 물으면 **허용**을 누르세요. 설치 스크립트와 `ipchal` 명령만 실행합니다.

✗ 표시가 나오면 그 줄을 그대로 Claude에게 물어보세요 ("이거 무슨 뜻이야?"). 그래도 안 되면 그 화면을 담당자에게 보내 주세요.

## 3. 데이터 둘러보기

이렇게 말해 보세요.

- "어떤 데이터가 있어?"
- "공고 테이블 컬럼 설명해 줘"
- "최근 한 달 개찰된 공고 10건만 보여 줘"
- "낙찰하한율별로 공고가 몇 건인지 세어 줘"

알아 두면 좋은 점:

- **조회만 합니다.** 데이터를 바꾸거나 지울 수 없습니다.
- **조회량:** BigQuery는 읽은 양만큼 비용이 듭니다. 많이 읽는 조회는 Claude가 예상 조회량(GB)을 먼저 보여 주고 진행할지 묻습니다.
- **y:** 모델이 맞히려는 값입니다. 최종 낙찰금액을 낙찰하한 금액과 비교한 값(%)이고, 아직 개찰 전인 공고는 비어 있습니다.
- **데이터 범위:** 기간마다 쌓인 정도가 다릅니다. 자세한 내용은 데이터 안내서를 보거나 "데이터가 어느 기간까지 있어?"라고 물어보세요.

## 4. feature 보기

**feature**는 모델이 공고 하나를 보고 계산하는 "참고 값"입니다. 예를 들어 "같은 낙찰하한율 공고의 최근 20건 평균 y"가 하나의 feature입니다.

- "어떤 feature가 있어?"
- "운영에서 지금 어떤 feature 써?"
- "전체_sma20 이 뭐야? SQL도 보여 줘"

feature에는 상태가 있습니다.

| 상태 | 뜻 |
|---|---|
| 검사통과 | 실험에 쓸 수 있음 |
| 초안 | 검사에서 문제가 나와 고쳐야 함 (실험에 못 씀) |
| 폐기 | 더 이상 쓰지 않음 |

---

## 5. feature 추가해 보기

아이디어를 말하면 Claude가 SQL로 만들어 미리 보여 주고, 검사를 거쳐 등록합니다.

**예시 대화**

> 나: 같은 공고기관의 최근 20건 평균 y를 feature로 추가해 줘
>
> Claude: (비슷한 feature가 있는지 확인 → SQL 작성 → 최근 한 달 공고로 미리보기)
> "최근 한 달 공고 1,234건 중 1,100건에 값이 나왔고, 나머지는 과거 기록이 없는 기관이라 비어 있습니다. 이름은 `기관_최근20_평균`, 설명은 '같은 공고기관의 직전 20건 평균 y'로 등록할까요?"
>
> 나: 응
>
> Claude: (검사 몇 분, 약 4 GB 조회) "검사를 통과했습니다. 이제 실험에 쓸 수 있습니다."

등록할 때 자동으로 하는 검사는 다음과 같습니다.

- **형식:** 공고마다 값이 정확히 하나씩 나오는지
- **빈 값:** 값이 전부 비어 있지 않은지
- **미래 정보:** 공고 개찰일 기준 **7일 전보다 앞선 결과만** 썼는지. 개찰 직전 결과를 쓰면 실제 예측할 때는 알 수 없는 정보를 쓰는 셈이라 막습니다.
- **비용:** 계산할 때 너무 많이 조회하지 않는지

검사에 실패하면 **초안**으로 저장되고 Claude가 이유를 설명합니다. "고쳐 줘"라고 하면 고쳐서 다시 검사합니다.

> 내가 만든 feature는 **실험용 목록**에만 들어갑니다. 운영 중인 모델에는 아무 영향이 없습니다.

## 6. 모델 만들어 비교하기

- "기관_최근20_평균이랑 낙찰하한율로 모델 만들어 줘"
- "지금 운영 모델 feature에 기관_최근20_평균을 더하면 좋아져?"

모든 실험은 **같은 기준**으로 평가됩니다. 데이터의 마지막 12개월로 평가하고, 그 이전 데이터로 학습합니다. 몇 분에서 수십 분 걸리며, 끝나면 비교표가 나옵니다.

| 비교 대상 | 뜻 |
|---|---|
| 경험 분포 | feature 없이 과거 결과 분포만으로 찍었을 때 |
| 운영 중 | 지금 서비스에서 쓰는 모델 |
| 이번 실험 | 내가 고른 feature 조합 |

보는 법:

- **0.01 top-5 적중률 (주 지표):** 모델이 고른 0.01 폭 구간 5개 안에 실제 결과가 들어간 비율입니다. 높을수록 좋습니다.
- **0.1 top-5 적중률:** 같은 방식이지만 0.1 폭 구간입니다.
- **± 오차:** 차이가 이 범위보다 작으면 "우연일 수 있다"는 뜻입니다. Claude가 함께 판단해 줍니다.

실험 기록은 자동으로 남습니다. "내 실험 목록 보여 줘", "실험 exp-20261108-1530… 다시 보여 줘"처럼 다시 볼 수 있습니다.

## 7. 운영 반영: 요청 → 승인

운영 모델보다 **확실히** 좋아졌을 때만 반영합니다. 요청과 승인은 누구나 할 수 있습니다.

> 나: 이 실험 서빙해 줘
>
> Claude: (비교표를 다시 설명) "요청 이유를 한두 문장으로 알려 주세요."

요청은 "이 실험을 올리자"는 기록일 뿐이라 **운영은 아직 그대로**입니다. 요청 목록은 "서빙 요청 보여 줘"로 볼 수 있습니다.

### 승인

> 나: 승인해 줘
>
> Claude: "승인하면 이 모델이 **운영 모델**이 됩니다. 지금 운영 모델보다 0.01 적중률이 0.8%p 높지만 우연 범위 안이라 좋아졌다고 말하기 어렵습니다. 되돌릴 수는 있지만 새 버전 파일은 영구히 남습니다. 확신이 없으면 팀과 먼저 이야기해 보세요. 운영에 반영할까요?"
>
> 나: 응, 반영해 줘

Claude는 승인 직전에 **항상** 이렇게 무엇이 바뀌는지와 근거를 설명하고 다시 묻습니다. 분명히 "예"라고 답해야 진행됩니다.

승인하면 그 feature 조합으로 **전체 기간 데이터로 다시 학습**한 뒤 새 버전(v01, v02 …)으로 저장하고 운영을 전환합니다. 몇 분 걸립니다.

---

## 8. 반려·되돌리기

- "반려해 줘, 이유는 …": 요청을 반려하고 이유를 남깁니다.
- "v01로 되돌려 줘": 예전 버전으로 되돌립니다. 이때도 Claude가 먼저 확인합니다. 예전 파일은 지워지지 않고 남아 있어서 다시 돌아갈 수도 있습니다.
- "서빙 상태 보여 줘": 지금 운영 중인 버전과 그 feature를 봅니다.

승인 후 실제 서비스에서 무엇이 바뀌는지는 [운영 워크플로](operations-workflow.md)를 보세요.

---

## 9. 지켜 주세요

- 모든 작업은 Claude와 `ipchal` 명령으로만 합니다. Google Cloud 콘솔이나 다른 도구로 직접 테이블을 고치지 마세요. 공유 계정은 권한이 커서, 프로그램 밖에서 하면 실수를 막을 수 없습니다.
- 조회량 안내가 나오면 숫자를 보고 판단하세요. 이유를 모르겠는 큰 조회(수십 GB 이상)는 담당자에게 먼저 물어보세요.
- 운영 반영(승인·되돌리기)은 팀 전체에 영향을 줍니다. 확신이 없으면 팀과 먼저 이야기하세요.
- 설정 파일·데이터 안내서·로그인 정보는 공유하지 마세요.

## 10. 자주 묻는 질문

**Q. "버전이 다릅니다"라고 나와요.**
"업데이트해 줘"라고 말하면 Claude가 최신 버전으로 다시 설치합니다.

**Q. 로그인 창이 안 떠요 / 로그인이 풀렸어요.**
"로그인 다시 해 줘"라고 말하세요.

**Q. 실험이 너무 오래 걸려요.**
feature가 많을수록 오래 걸립니다. 처음에는 2~5개로 시작하세요.

**Q. 내가 만든 feature를 지우고 싶어요.**
"이 feature 폐기해 줘"라고 하면 폐기 상태가 됩니다. 기록은 남습니다.

**Q. 다 지우고 싶어요.**
플러그인을 삭제하면 프로그램, Python, 설정 파일, 로그인 정보가 들어 있는 전용 폴더도 기본적으로 같이 지워집니다. 작업 폴더에 만든 SQL 파일은 직접 지우면 됩니다.

**Q. Windows에서도 되나요?**
됩니다. 설치 과정만 조금 다르고, Claude가 운영체제에 맞게 진행합니다. 모델 라이브러리를 불러올 수 없다는 메시지가 나오면, 점검 결과에 나온 Microsoft 링크로 구성 요소를 설치하세요.
