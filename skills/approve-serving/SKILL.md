# 서빙 승인

요청된 모델을 운영에 반영하거나 되돌린다. 누구나 할 수 있다. 그래서 반영 직전의 확인 대화가 유일한 안전장치다. 아래 "반영 전 확인"을 절대 건너뛰지 않는다.

## 반영 전 확인 (승인·되돌리기 모두, 매번)

`ipchal serving approve` 나 `ipchal serving rollback` 을 실행하기 직전에, 아래 내용을 쉬운 말로 전하고 사용자의 분명한 "예"를 받는다.

- **무엇이 바뀌는지:** "승인하면 이 모델이 **운영 모델**이 됩니다. 실험과 달리 실제 서비스가 쓰는 모델이 바뀌고, 팀 전체가 이 결과를 보게 됩니다."
- **근거:** 지금 운영 모델과 비교한 점수 차이. 차이가 표준오차 2배보다 작으면(우연 범위) "좋아졌다고 말하기 어렵습니다"라고 분명히 말한다.
- **되돌릴 수 있는 것과 없는 것:** 운영 전환은 되돌리기로 되돌릴 수 있다. 하지만 새 버전 파일(vNN)은 지워지지 않고 영구히 남는다.
- **신중하게:** "확신이 없으면 승인하지 말고 팀과 먼저 이야기해 보세요"라고 권한다.

그다음 "운영에 반영할까요?"라고 예/아니오로 묻는다. 분명한 "예"("응", "네, 반영해 줘" 등)를 받은 경우에만 실행한다. 모호한 답이거나, 이전 대화에서 받은 동의이거나, 다른 실험에 대한 동의라면 다시 묻는다.

## 먼저 할 일

1. `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json` 을 읽어 `version` 값을 확인한다.
2. `ipchal doctor --plugin-version <그 버전>` 을 실행한다.
3. 실패하면(✗ 표시) 이 단계로 더 진행하지 말고 setup 스킬로 안내한다. 버전이 다르다고 나오면 `uv tool install --managed-python --python 3.12 --reinstall https://github.com/lkhoony/ipchal-lab/archive/refs/heads/main.zip` 을 안내하고 다시 확인한다.

## 안전 규칙

`ipchal` 명령만 쓴다. bq·gcloud·gsutil을 직접 실행하지 않는다. 쓰기·삭제는 명령이 제공하는 것만.

## 말하는 방식

결과는 비개발자가 알아듣는 쉬운 한국어로 설명한다. 전문 용어는 처음 나올 때 한 번 풀어 쓴다.
명령이 `--yes-bytes N` 을 붙여 다시 실행하라는 안내(예상 조회량이 한도를 넘는다는 뜻)를 출력하면, 예상 조회량을 GB로 바꿔 사용자에게 보여 주고 진행할지 먼저 묻는다. 사용자가 동의한 뒤에만 그 옵션을 붙여 다시 실행한다.


## 단계

1. 요청 목록: `ipchal serving list`. 현재 서빙 상태: `ipchal serving status`.
2. 검토할 요청의 비교표를 `ipchal experiment show <실험번호>` 로 보여 주고, 요청 이유와 함께 쉬운 말로 설명한다 (기준 대비 좋아졌는지, 우연 범위 안인지, 쓰인 feature).
3. 위 "반영 전 확인"을 한다.
4. 예 → `ipchal serving approve <실험번호>`. 전체 기간 데이터로 다시 학습해 새 버전 파일을 올리므로 몇 분 걸릴 수 있다. 끝나면 새 서빙 버전을 알려 준다. 조회량 안내가 나오면 위의 `--yes-bytes` 규칙을 따른다.
5. 아니오 → 그대로 두거나, 사용자가 원하면 `ipchal serving reject <실험번호> --note "<반려 이유>"` 로 반려를 기록한다.

## 되돌리기

문제가 생기면 이전 버전으로 되돌릴 수 있다. 어떤 버전이 있는지 `ipchal serving status` 로 확인하고, 어느 버전으로 돌아갈지 정한 뒤, 위 "반영 전 확인"을 거쳐 `ipchal serving rollback <버전>` 을 실행한다. 이전 버전 파일은 저장소에 그대로 남아 있어 필요하면 다시 전환할 수 있다.
