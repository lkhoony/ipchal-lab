# 데이터 살펴보기

데이터 안내서와 읽기 전용 조회로 어떤 데이터가 있는지 설명한다.

## ipchal 실행 방법

`ipchal` 은 이 플러그인의 데이터 폴더에 설치된 것만 쓴다. PATH에 있는 다른 `ipchal`·`uv` 는 쓰지 않는다. 이 문서에서 `ipchal <명령>` 이라고 쓴 것은 아래처럼 실행한다.
- Mac: `"${CLAUDE_PLUGIN_DATA}/bin/ipchal" <명령>`
- Windows (PowerShell): `& "${CLAUDE_PLUGIN_DATA}\bin\ipchal.exe" <명령>`

설치·업데이트 (uv·Python·ipchal을 모두 데이터 폴더 안에 받는다. 몇 분 걸린다):
- Mac: `sh "${CLAUDE_PLUGIN_ROOT}/scripts/install.sh" "${CLAUDE_PLUGIN_DATA}"`
- Windows: `powershell -ExecutionPolicy Bypass -File "${CLAUDE_PLUGIN_ROOT}\scripts\install.ps1" "${CLAUDE_PLUGIN_DATA}"`

설치 끝에 "PATH에 없다"는 경고가 나와도 정상이다. PATH나 셸 설정을 바꾸지 않는다 (플러그인을 지우면 깨끗이 지워지도록).

## 먼저 할 일

1. `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json` 을 읽어 `version` 값을 확인한다.
2. `ipchal doctor --plugin-version <그 버전>` 을 실행한다.
3. 실패하면(✗ 표시) 이 단계로 더 진행하지 말고 setup 스킬로 안내한다. `ipchal` 이 아직 없거나 버전이 다르다고 나오면 위의 설치·업데이트 명령을 실행하고 다시 확인한다.

## 안전 규칙

`ipchal` 명령만 쓴다. bq·gcloud·gsutil을 직접 실행하지 않는다. 쓰기·삭제는 명령이 제공하는 것만.

## 비용 확인 (질문마다, 작업 전에)

이 스킬의 작업을 시작하기 전에 `ipchal cost` 를 실행하고, 이번 달 GCP 사용액·한도·남은 금액을 한 줄로 먼저 알린다.
- 데이터를 읽는 명령은 실행 전에 스스로 "이번 달 사용액 + 이번 조회 예상" 이 월 한도를 넘는지 확인하고, 넘으면 실행하지 않는다. 출력 첫 줄의 "이번 달 GCP 사용액 …" 과 끝의 "이번 작업 조회 … GB, 약 …원" 을 사용자에게 그대로 전한다.
- "월 한도를 넘어 실행하지 않았습니다" 나 "사용액을 확인할 수 없어 실행하지 않았습니다" 가 나오면 진행하지 말고, 그 내용을 담당자에게 전하라고 안내한다. 한도를 우회하는 방법(설정 변경 등)을 쓰지 않는다.
- "다른 서비스 비용은 빠져 있음" 이 보이면, 저장·Cloud Run 같은 비용은 포함되지 않은 금액이라고 함께 말한다.

## 말하는 방식

결과는 비개발자가 알아듣는 쉬운 한국어로 설명한다. 전문 용어는 처음 나올 때 한 번 풀어 쓴다.
명령이 `--yes-bytes N` 을 붙여 다시 실행하라는 안내(예상 조회량이 한도를 넘는다는 뜻)를 출력하면, 예상 조회량을 GB로 바꿔 사용자에게 보여 주고 진행할지 먼저 묻는다. 사용자가 동의한 뒤에만 그 옵션을 붙여 다시 실행한다.


## 하는 일

1. `ipchal data guide` 로 데이터 안내서를 읽고, 테이블이 무엇을 담는지 쉬운 말로 설명한다.
2. 테이블 목록이 필요하면 `ipchal data tables`, 컬럼이 궁금하면 `ipchal data describe <키>` (키는 `TABLE_...`/`VIEW_...` 형태).
3. 샘플·요약·통계는 **모델용 기준 뷰 `model_base` 에서** `ipchal data query "<SELECT 문>"` 으로 조회한다. 읽기 전용이다.
   - 데이터셋 이름 없이 `FROM model_base` 로 쓴다. 공고 1건이 1행이고, 공고 정보와 결과(예가율)가 정리되어 있다.
   - 평균·분포·추이·그룹 비교·상관관계 같은 통계 분석도 model_base 조회 결과로 한다. 계산은 가능한 한 SQL 안에서 한다 (`AVG`, `APPROX_QUANTILES`, `STDDEV`, `CORR`, `COUNTIF` 등).
   - 한글 컬럼 이름은 반드시 `백틱`으로 감싼다 (예: `` `개찰일시` ``).
   - 처음에는 `LIMIT 10` 이나 날짜 조건으로 작게 시작하고, 필요한 컬럼만 고른다.
   - 데이터 범위: 2016년부터 지금까지 빈 구간 없이 있다. 가장 최근 공고는 아직 개찰 전이라 결과 컬럼(예가율 등)이 비어 있다.
4. 결과 표는 한두 문장으로 요약해 의미를 설명한다.

## 원본 테이블은 요청할 때만

- 사용자가 "원본", "raw", 특정 원본 테이블(공고 목록, 개찰 결과 등)을 분명히 말하거나, model_base 에 없는 정보(업체별 투찰 내역 등)가 꼭 필요할 때만 원본 테이블을 쓴다.
- 원본을 읽기 전에 반드시 되묻는다: "model_base(가공된 기준 데이터)가 아니라 원본 테이블 ○○을 조회할까요? 원본은 조회량이 크고 같은 공고가 수집일별로 여러 번 들어 있을 수 있습니다." 분명한 "예"를 받은 뒤에만 `ipchal data query --raw "<SELECT 문>"` 으로 실행한다.
- `--raw` 없이 원본 테이블을 읽으면 명령이 거부한다. 거부되면 우회하지 말고 위처럼 사용자에게 묻는다.
- 원본 테이블에는 대표자명·연락처·주소 같은 개인정보 열이 있다. 결과에 보여 주지 않는다.

## 자주 헷갈리는 점

- `최종낙찰금액` 은 개찰 1순위 업체의 투찰금액이다.
- `참여업체수` 는 개찰 결과 행의 개수다.
- **예가율**: 최종낙찰금액이 낙찰하한가(기초금액 × 낙찰하한율 ÷ 100)보다 몇 % 높은지. 모델이 맞히려는 값이다. 사용자에게는 항상 "예가율"이라고 말하고, SQL 열 이름은 `y` 이므로 조회할 때 `y AS 예가율` 처럼 별칭을 붙인다 (`data query` 결과의 `y` 열은 자동으로 예가율로 바뀐다). 아직 개찰 전인 공고는 비어 있다.
